# Slice 1 — OpenAI chat backend + key field + temperature removal

Type: AFK · Tracer bullet · Source: PRD-OpenAIKey.md

## What to build

The thin end-to-end path that proves the whole feature: a user pastes their own OpenAI API key into the app, the cheapest supported model is preselected, they ask a question about the campaign, and they get an answer generated by OpenAI. This replaces the Ollama backend entirely.

Behind the scenes this swaps the LLM backend from local Ollama to hosted OpenAI while keeping the existing `LLMHandler` interface intact, so `TTRPGChatbot` and `SummaryHandler` are unaffected. The `ollama` and `langchain_ollama` dependencies are removed; `openai` and `langchain_openai` are added. `LLMHandler` internals are reimplemented against `ChatOpenAI`:

- `get_available_models()` returns a hardcoded, verified list — `gpt-5.4-nano` (default), `gpt-5.4-mini`, `gpt-5.4` — with no network call and no key required to render.
- `is_thinking_model()` returns `True` for all supported models.
- `get_context_tokens()` returns the existing `16384` clamp for all models.
- `load_model()` takes an explicit `api_key` parameter, validates the model name against the hardcoded list, and constructs a `ChatOpenAI`.
- `invoke_model()` preserves the `prompt | model | StrOutputParser()` chain.

The temperature control is removed entirely (GPT-5 reasoning models reject non-default `temperature` with a 400), so `model_temperature` is dropped from the UI, session-state init, `__save_user_data`, `load_model`, and `CampaignSummarizer`. A `st.text_input(type="password")` for the API key is added at the top of the sidebar "🔧 Model Options" section, stored to `st.session_state.openai_api_key` (session-only, never persisted), and threaded into every `load_model` call site.

The PyInstaller spec is updated minimally so the build doesn't break.

## Acceptance criteria

- [ ] `ollama` and `langchain_ollama` are removed from `requirements.txt`; `openai` and `langchain_openai` are added.
- [ ] No remaining references to `ollama` or `langchain_ollama` anywhere in `src/`.
- [ ] The sidebar shows a password-masked OpenAI API key field storing to session state and never written to `user_data.json`.
- [ ] The model dropdown lists exactly `gpt-5.4-nano`, `gpt-5.4-mini`, `gpt-5.4`, with `gpt-5.4-nano` preselected on first run.
- [ ] `load_model(model_name, api_key, disable_thinking=False)` constructs a `ChatOpenAI` and raises `ValueError` for a model not in the hardcoded list.
- [ ] No `temperature` is sent to OpenAI; the temperature slider is gone and `model_temperature` no longer appears in session state, persistence, or handler calls.
- [ ] With a valid key and a selected model, asking a chat question returns an OpenAI-generated answer with references, using the existing retrieval flow.
- [ ] `conftest.py` mocks `openai`/`langchain_openai` (FastEmbed mocks retained); `test_llm_handler.py` is rewritten to the new surface and passes.
- [ ] The PyInstaller spec no longer references Ollama and does not break the build config.
